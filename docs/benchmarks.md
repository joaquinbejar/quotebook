# quotebook compute-unit costs

Generated by `make bench` (`program/tests/cu.rs`) in LiteSVM. Each figure is the `compute_units_consumed` of a transaction holding only that instruction (for `settle`, also the ed25519 precompile instruction before it), including the system and token program CPIs. Keys and mint addresses of the creation rows are fixed, so the PDA bump searches (about 1,500 CU per attempt) are the same on every run; with other keys a creation can cost a few thousand CU more. `settle` does no bump search, so its cost does not depend on the keys. The precompile itself consumes no compute units (measured below); it costs one signature in the transaction fee.

| Instruction | Case | CU |
| --- | --- | ---: |
| `init_config` | upgrade-authority gate + config PDA search + create | 4645 |
| `create_series` | two SPL Token mints | 7892 |
| `create_series` | Token-2022 base with MetadataPointer + TokenMetadata | 8460 |
| `init_maker` | maker and delegate PDA searches + create (2,120 bytes) | 4554 |
| `cancel_nonce` | inside the window, no slide | 1676 |
| `cancel_nonce` | slides 64 nonces (one word) | 1719 |
| `cancel_all` | slides 100 nonces | 1748 |
| `cancel_all` | slides 16,383 nonces, unaligned, wrapping (worst case) | 1788 |
| `cancel_all` | slides a whole window or more (clears the ring) | 1696 |
| `set_series_paused` | config and series PDA re-derivation | 3254 |
| `set_config` | config PDA re-derivation | 1684 |
| `settle` | SPL Token both legs, maker bid | 8593 |
| `settle` | SPL Token both legs, maker ask | 8593 |
| `settle` | SPL Token, worst case (16,383-nonce unaligned slide, costlier side) | 8627 |
| `settle` | Token-2022 both legs, plain accounts, maker bid | 11998 |
| `settle` | Token-2022, worst case (as SPL, plus every allowlisted mint extension and three account extensions) | 18188 |
| `ed25519 precompile` | one signature over a 208-byte quote, alone in a transaction | 0 |

The precompile's 0 CU is not free: the runtime charges each precompile signature like a transaction signature. A precompile-only transaction signed by its fee payer pays 10000 lamports (two signatures); a `settle` transaction signed by the fee payer and the taker pays 15000 lamports (three signatures). Priority fees come on top, priced per compute unit the transaction requests.

## Comparison with matchbook (cited, not run here)

matchbook's own LiteSVM bench, `docs/benchmarks.md` at matchbook commit `72efa6d` (branch
`redesign`), reports:

| matchbook operation | CU |
| --- | ---: |
| IOC, 1 fill | 1,660 |
| Swap from a wallet, no account, 1 fill | 4,487 |

Reproduce in matchbook: `cargo build-sbf --manifest-path program/Cargo.toml` then
`cargo test -p matchbook-program --test bench -- --nocapture`.

The designs differ, so the numbers answer different questions. matchbook is an order book:
both sides deposit into the program first, and an IOC fill moves balances inside its own
accounts without a token CPI; its wallet swap adds the token transfers. quotebook has no
deposits and no book: a `settle` verifies a maker-signed RFQ quote and moves both legs with
two token-program CPIs from the parties' wallets, so the nearest matchbook figure is the
wallet swap. This is a citation from another repository's bench, not a same-VM measurement.
