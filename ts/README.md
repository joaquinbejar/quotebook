# @quotebook/sdk (TypeScript)

The TypeScript SDK for quotebook (docs/PLAN-improvements.md, I8). It is not published to npm:
publishing is irreversible and needs its own GO.

| What | Functions |
| --- | --- |
| Quotes | `encodeQuote`, `decodeQuote` (canonical 208 bytes) |
| Signatures | `signQuote`, `verifyQuoteSignature` (Ed25519, WebCrypto via `@solana/kit`) |
| Precompile | `precompileData`, `precompileInstruction` (self-contained, every index `0xFFFF`) |
| `settle` | `settleData`, `settleInstruction` (the program's account order) |
| PDAs | `configPda`, `seriesPda`, `makerStatePda`, `delegatePda` |
| Accounts | `decodeConfig`, `decodeSeries`, `decodeMakerState` (with `check(nonce)`, as `settle` judges it) |
| Fill events | `encodeFillEvent`, `decodeFillEvent`. Context-free: for provenance (which program logged it, and whether the transaction and every enclosing frame succeeded), follow the Rust `quotebook-sdk::events::fill_events` rules |

Integers that can exceed 2^53 are `bigint`.

## How it is checked

- `ts/vectors/vectors.json` is generated by the Rust crates:
  `cargo run -p quotebook-sdk --example vectors`. `make vectors-check` fails if it is stale.
- `test/vectors.test.ts` asserts byte equality on every vector: encodings, precompile data,
  `settle` data and account metas, PDAs and bumps, account and event decodes, and Ed25519
  signatures. TypeScript reproduces Rust's signatures exactly, because Ed25519 is
  deterministic.
- `scripts/emit-settle.ts` builds a `[precompile, settle]` transaction with this SDK alone.
  `sdk/tests/ts_settle.rs` replays it against the real program in LiteSVM and checks the
  balances.
- `make ts-check` runs `npm ci`, `tsc --noEmit`, the tests, and requires the emitted
  transaction to equal the committed one. It is part of `make pre-push`, and runs in CI's `ts`
  job on Node 26.13.0.

Versions (exact, `package-lock.json`; the latest stable on npm, checked 2026-11-02):
`@solana/kit` 8.6.0, `typescript` 7.0.2, `@types/node` 26.6.6.
